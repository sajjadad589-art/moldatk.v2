# M04 payment allocation foundation

Pure integer IQD payment preview follows the existing oldest-first allocation. It rejects overpayments rather than silently clamping them, requires the recorded balance to reconcile with complete invoice history, preserves collected cash, excludes cancelled and free invoices, allows historical debt settlement in a free current month, and requires an active tariff and existing current invoice. Seven domain tests added. A missing current invoice must be generated authoritatively before preview; duplicate active monthly invoices or inconsistent rows require reconciliation. No payment mutation, cashbox write, receipt generation or UI is enabled. Server must repeat allocation within one transaction with immutable idempotency key, payment and allocation rows, invoice/account balances, audit and verified cashbox projection. Explicit settlement, waivers and cancellations remain separate operations. No production change.
