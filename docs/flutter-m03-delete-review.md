# M03 deletion policy review

The legacy service-role permanent delete removes related audit logs and cascades financial rows, with a separate cleanup path. A replacement must not call it blindly. The client preflight is intentionally conservative: it requires complete invoice history, a verified row version and reset epoch, zero outstanding, no paid or nonzero invoice and an explicit verified payment-reference count. Unknown references block the request; even a positive cancelled invoice requires manual review. A clear preflight permits server review only, not deletion. No data is deleted. Next: verify all incoming foreign keys, direct and indirect payment/allocation/cashbox/receipt references, legacy delete cleanup and reset/legacy-write serialization; choose explicit retention/archive policy for financially active records before exposing a mutation. Five tests are added and the prior service edit formatter differences are corrected.
