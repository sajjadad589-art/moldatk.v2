# M04 payment reversal review

Narrow owner-only candidate reverses the latest verified Flutter payment only if its after-ledger still matches, current cycle and epoch match, and affected invoices did not have earlier cash (previous payment-date provenance is not yet stored). It restores the exact prior amounts and statuses, recomputes account projections, records reason and one negative cashbox event through the existing audit projection, and retains original payment and allocation history. Replays are idempotent; collection replay after reversal fails closed. No public endpoint or production change. Blockers: full legacy/portal cancelled-receipt display, accurate earlier-date restoration, cashbox reset semantics, live concurrency/RLS and complete staging verification. This is not a general historical refund implementation.
